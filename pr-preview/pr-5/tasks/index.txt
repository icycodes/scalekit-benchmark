## Background
Scalekit SaaSKit (Full-Stack Auth) issues a short-lived `accessToken`, a long-lived `refreshToken`, and an `idToken` after a successful hosted login. When the access token nears expiry, your app can exchange the refresh token for a brand-new pair of tokens by calling the SDK's `refreshAccessToken` method — without forcing the user to sign in again.

In this task you will build a small Express.js web application that wires SaaSKit end-to-end **and** exposes a user-visible "Refresh access token" control on the dashboard. A real human user (driven by a browser agent during verification) will sign in with the preconfigured test user + static OTP, land on a protected dashboard that shows the access token's current `iat` (issued-at) and `exp` (expires-at) claim values, click "Refresh access token", and see the dashboard re-render with new `iat`/`exp` values that come from a freshly issued token returned by Scalekit's refresh API.

The Scalekit environment has been preconfigured with the following SaaSKit fixtures (use them verbatim, do **NOT** invent new credentials, do **NOT** introduce any environment variables that are not provided):

* Allowed callback URL: `http://localhost:3000/callback`
* Initiate-login URL: `http://localhost:3000/login`
* Post-logout URL: `http://localhost:3000/goodbye`
* Test user email: `zealt-user01+sktest@test.com`
* Static OTP for the test user: `424242`

Scalekit SDK credentials are provided through the environment variables `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, and `SCALEKIT_CLIENT_SECRET`. No other Scalekit environment variables exist.

## Requirements
- Build an Express.js application (Node.js) using the official `@scalekit-sdk/node` SDK. TypeScript or plain JavaScript is acceptable.
- The app **MUST** listen on port `3000` so it matches the registered SaaSKit URLs above.
- Implement the following routes:
  - `GET /` — a public landing page. Must render an HTML page that contains a visible sign-in entry point (link/button) whose target is `GET /login`.
  - `GET /login` — builds the SaaSKit authorize URL via the Scalekit SDK with the registered callback URL `http://localhost:3000/callback` and scopes that include `openid`, `profile`, `email`, and `offline_access` (the `offline_access` scope is required to receive a refresh token), then HTTP-redirects (302/303/307) the user to that URL. The authorize URL **MUST** be generated by the SDK (do not hand-build it).
  - `GET /callback` — receives `?code=<...>`, exchanges it via the Scalekit SDK (`authenticateWithCode`), stores `accessToken`, `refreshToken`, and `idToken` in **HttpOnly** cookies, and HTTP-redirects to `/dashboard`.
  - `GET /dashboard` — a protected route:
    * If the request has no `accessToken` cookie (or no `idToken` cookie), HTTP-redirect to `/login`.
    * Otherwise, render an HTML page that visibly contains ALL of the following: the signed-in user's email (decoded from the `idToken` `email` claim), the current access token's `iat` claim value (the issued-at UNIX timestamp), the current access token's `exp` claim value (the expires-at UNIX timestamp), a visible "Refresh access token" link or button that points to `GET /refresh-session`, and a visible "Sign out" / "Logout" link or button targeting `GET /logout`.
    * Each timestamp on the dashboard **MUST** be displayed as the raw integer UNIX seconds value (for example: `iat: 1758264947`, `exp: 1758265247`). You may additionally render a human-readable form, but the raw integer **MUST** be present in the page text so it can be compared verbatim.
  - `GET /refresh-session` — exchanges the user's `refreshToken` cookie for a fresh token pair:
    * If the `refreshToken` cookie is missing or empty, HTTP-redirect to `/login`.
    * Otherwise, call the Scalekit SDK's refresh method (`scalekit.refreshAccessToken(refreshToken)`) to obtain a new `accessToken`, `refreshToken`, and (when returned) `idToken`.
    * Overwrite the `accessToken`, `refreshToken`, and `idToken` cookies (still **HttpOnly**) with the freshly issued values, then HTTP-redirect to `/dashboard`.
    * If the SDK call throws or returns an invalid result, clear the session cookies and HTTP-redirect to `/login` (do not crash the request handler).
  - `GET /logout` — produce the Scalekit logout URL via `scalekit.getLogoutUrl(idToken, 'http://localhost:3000/goodbye')` **BEFORE** clearing cookies, then clear `accessToken`, `refreshToken`, and `idToken` cookies and HTTP-redirect the browser to the logout URL.
