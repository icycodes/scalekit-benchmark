# Scalekit SaaSKit: Build an Express.js Web App that Drives Enterprise SSO via Home Realm Discovery ## Background Scalekit SaaSKit (Full-Stack Auth) supports **Enterprise SSO** with **Home Realm Discovery (HRD)**: when a user signs in with an email whose domain is registered to an organization that has an SSO connection, Scalekit automatically routes that user to the organization's identity provider instead of any first-party authentication method. For local testing, Scalekit provides an IdP Simulator that acts as a stand-in IdP for the preconfigured Test Organization. In this task you will build a small Express.js web application that wires SaaSKit end-to-end so a real human user (driven by a browser agent during verification) can: 1. Open the landing page. 2. Click "Sign in with SSO". 3. Type an email belonging to the test organization's registered domain on Scalekit's hosted login page. 4. Be automatically redirected by Scalekit (via Home Realm Discovery) to Scalekit's IdP Simulator. 5. Complete authentication on the IdP simulator. 6. Land on a protected dashboard that displays their signed-in email and their Scalekit organization id (the `oid` claim from the issued ID token). 7. Sign out cleanly via the Scalekit logout endpoint and end up on a public goodbye page. The Scalekit environment has been preconfigured in the dashboard with the following fixtures (use them verbatim, do **NOT** invent new credentials, do **NOT** introduce any environment variables that are not provided): * Allowed callback URL: `http://localhost:3000/callback` * Initiate-login URL: `http://localhost:3000/login` * Post-logout URL: `http://localhost:3000/goodbye` * Test organization registered domains for Home Realm Discovery: `example.com`, `example.org` * Test organization SSO connection is wired to Scalekit's hosted IdP Simulator The Scalekit SDK credentials are provided through the environment variables `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, and `SCALEKIT_CLIENT_SECRET`. No other Scalekit environment variables exist. ## Requirements * Build an Express.js application (Node.js) using the official `@scalekit-sdk/node` SDK. TypeScript or plain JavaScript is acceptable. * The app **MUST** listen on port `3000` so it matches the registered callback / initiate-login / post-logout URLs above. * Implement the following routes: * `GET /` — a public landing page. It must render an HTML page that contains a visible "Sign in with SSO" entry point (a link or button) that takes the user to `GET /login`. * `GET /login` — builds the SaaSKit authorize URL via the Scalekit SDK with the registered callback URL `http://localhost:3000/callback` and a scope set that includes `openid`, `profile`, `email`, and `offline_access`, then HTTP-redirects (302/303/307) the user to that URL. The authorize URL **MUST** be generated by the SDK (do not hand-build it). * `GET /callback` — receives `?code=<...>`, exchanges it via the Scalekit SDK (`authenticateWithCode`), stores `accessToken`, `refreshToken`, and `idToken` in **HttpOnly** cookies, then HTTP-redirects to `/dashboard`. * `GET /dashboard` — a protected route. If the request has no valid session (no `idToken` cookie), redirect to `/login`. If authenticated, render an HTML page that shows BOTH the signed-in user's email (decoded from the `idToken` claim `email`) AND the user's Scalekit organization id (decoded from the `idToken` claim `oid`), and a visible "Sign out" / "Logout" link or button targeting `GET /logout`. * `GET /logout` — produce the Scalekit logout URL via `scalekit.getLogoutUrl(idToken, 'http://localhost:3000/goodbye')` BEFORE clearing cookies, then clear `accessToken`, `refreshToken`, and `idToken` cookies, and HTTP-redirect the browser to the logout URL. * `GET /goodbye` — a public page that visibly confirms the user has signed out (must contain a clearly visible "signed out" / "goodbye" / "logged out" message). ## Implementation Hints * Install the SDK with `npm install @scalekit-sdk/node express cookie-parser` (add `typescript`/`tsx` if you want to write TypeScript). * Initialize the SDK with `new ScalekitClient(process.env.SCALEKIT_ENV_URL!, process.env.SCALEKIT_CLIENT_ID!, process.env.SCALEKIT_CLIENT_SECRET!)`. * The redirect URI passed to `getAuthorizationUrl` and `authenticateWithCode` **MUST** be `http://localhost:3000/callback` exactly — protocol, host, port, and path must match the dashboard allow-list (do not substitute `127.0.0.1`). * You do not have to detect SSO yourself; the Scalekit hosted login page performs Home Realm Discovery automatically once the user submits an email whose domain matches a registered organization domain (e.g., `example.com`). * The id token is a JWT.
