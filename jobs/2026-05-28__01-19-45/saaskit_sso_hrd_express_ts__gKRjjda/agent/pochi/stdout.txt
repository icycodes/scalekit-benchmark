For local testing, Scalekit provides an IdP Simulator that acts as a stand-in IdP for the preconfigured Test Organization. ### Route summary

| Route | Behaviour |
|---|---|
| `GET /` | Public landing page with a visible **"Sign in with SSO"** link → `/login` |
| `GET /login` | Calls `scalekit.getAuthorizationUrl(REDIRECT_URI, { scopes: ['openid','profile','email','offline_access'] })` and 302-redirects the browser to Scalekit's hosted login page, which performs Home Realm Discovery automatically |
| `GET /callback` | Receives `?code=`, exchanges it via `authenticateWithCode`, stores `idToken`, `accessToken`, and `refreshToken` as **HttpOnly** cookies, then redirects to `/dashboard` |
| `GET /dashboard` | Protected — if no `idToken` cookie, redirects to `/login`. Otherwise decodes the JWT payload (base64url, no crypto verification needed post-exchange) and renders the signed-in **email** and **oid** (`org_*`) claims alongside a **"Sign out"** link → `/logout` |
| `GET /logout` | Reads `idToken` cookie → builds logout URL via `scalekit.getLogoutUrl({ idTokenHint, postLogoutRedirectUri: 'http://localhost:3000/goodbye' })` **before** clearing cookies → clears all three cookies → 302-redirects browser to Scalekit's `/oidc/logout` endpoint |
| `GET /goodbye` | Public page confirming "You have been signed out / logged out. Goodbye!" with a link back to `/` |

### Key implementation details
- SDK initialized from `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, `SCALEKIT_CLIENT_SECRET` — no other env vars required.
- `REDIRECT_URI` is hard-coded to `http://localhost:3000/callback` everywhere it appears (matches dashboard allow-list exactly).
- All token cookies are `httpOnly: true, sameSite: lax` so they are not accessible to JavaScript.
- Logout URL is built **before** cookies are cleared so `id_token_hint` is always present.
- JWT payload is decoded with a pure base64url → JSON decode (no external JWT library needed).
- `package.json` has `"start": "node index.js"` so `npm start` launches the server on port 3000.
