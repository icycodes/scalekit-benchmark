# Scalekit SaaSKit: Build an Express.js Web App with a Token-Validated Protected JSON API ## Background Scalekit SaaSKit (Full-Stack Auth) issues an `access_token`, `id_token`, and `refresh_token` after a successful hosted login. A production-grade app must **validate** the access token server-side before trusting any embedded claims (the `validateAccessToken` SDK call). The same pattern is used to protect first-party JSON APIs that the browser dashboard calls on behalf of the signed-in user. In this task you will build a small Express.js web application that wires SaaSKit end-to-end **and** uses `scalekit.validateAccessToken()` as the gate for both a protected HTML dashboard and a protected JSON `/api/me` endpoint. A real human user (driven by a browser agent during verification) will sign in with the preconfigured test user + static OTP, land on the dashboard, see their own user information (which the dashboard pulls from the same `/api/me` JSON endpoint that an unauthenticated caller cannot reach), and finally sign out. The Scalekit environment has been preconfigured with the following SaaSKit fixtures (use them verbatim, do **NOT** invent new credentials, do **NOT** introduce any environment variables that are not provided): * Allowed callback URL: `http://localhost:3000/callback` * Initiate-login URL: `http://localhost:3000/login` * Post-logout URL: `http://localhost:3000/goodbye` * Test user email: `zealt-user01+sktest@test.com` * Static OTP for the test user: `424242` Scalekit SDK credentials are provided through the environment variables `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, and `SCALEKIT_CLIENT_SECRET`. No other Scalekit environment variables exist. ## Requirements * Build an Express.js application (Node.js) using the official `@scalekit-sdk/node` SDK. Must render an HTML page that contains a visible sign-in entry point (link/button) whose target is `GET /login`. * `GET /login` — builds the SaaSKit authorize URL via the Scalekit SDK with the registered callback URL `http://localhost:3000/callback` and scopes that include `openid`, `profile`, `email`, and `offline_access`, then HTTP-redirects (302/303/307) the user to that URL. The authorize URL **MUST** be generated by the SDK (do not hand-build it). * `GET /callback` — receives `?code=<...>`, exchanges it via the Scalekit SDK (`authenticateWithCode`), stores `accessToken`, `refreshToken`, and `idToken` in **HttpOnly** cookies, and HTTP-redirects to `/dashboard`. * `GET /dashboard` — a protected HTML route. The handler **MUST** validate the `accessToken` cookie via `scalekit.validateAccessToken(accessToken)` before rendering. If the cookie is missing or `validateAccessToken` returns falsy, HTTP-redirect to `/login`. If valid, render an HTML page that visibly contains BOTH the signed-in user's email (decoded from the `idToken` `email` claim) AND the user's Scalekit `sub` user id (decoded from the `idToken` `sub` claim), along with a visible "Sign out" / "Logout" link or button targeting `GET /logout`. * `GET /api/me` — a protected JSON endpoint: * The handler **MUST** read the `accessToken` cookie (or an `Authorization: Bearer <token>` header) and call `scalekit.validateAccessToken(accessToken)` to gate access. * If the access token is missing or `validateAccessToken` returns falsy, respond with HTTP **401** and a JSON body of the shape `{ "error": "<some message>" }` (the response content-type MUST be `application/json`). * If valid, respond with HTTP **200** and a JSON body that contains AT LEAST the fields `email` (from the `idToken` `email` claim) and `sub` (from the `idToken` `sub` claim). Extra fields are allowed. * `GET /logout` — produce the Scalekit logout URL via `scalekit.getLogoutUrl(idToken, 'http://localhost:3000/goodbye')` **BEFORE** clearing cookies, then clear `accessToken`, `refreshToken`, and `idToken` cookies and HTTP-redirect the browser to the logout URL. * `GET /goodbye` — a public page that visibly confirms the user has signed out (must contain a clearly visible "signed out" / "goodbye" / "logged out" message). ## Implementation Hints * Install the SDK with `npm install @scalekit-sdk/node express cookie-parser` (add `typescript`/`tsx` if you want to write TypeScript). * Initialize the SDK with `new ScalekitClient(process.env.SCALEKIT_ENV_URL!, process.env.SCALEKIT_CLIENT_ID!, process.env.SCALEKIT_CLIENT_SECRET!)`. ## Key Design Points

- **Centralized auth middleware** (`requireAuth`) handles both JSON (401) and HTML (redirect) failure modes based on the request path
- **Token validation** via `scalekit.validateAccessToken()` with all errors caught — never crashes the handler
- **JWT payload decoding** (base64url) extracts `email` and `sub` from the `idToken` without re-verifying (Scalekit already validates the access token)
- **Logout order**: logout URL generated from `idToken` *before* cookies are cleared, then cookies cleared, then redirect to Scalekit's `/oidc/logout` endpoint
- **All cookies** are `HttpOnly` + `SameSite=Lax`
- **Scopes**: `openid profile email offline_access` passed to `getAuthorizationUrl`
