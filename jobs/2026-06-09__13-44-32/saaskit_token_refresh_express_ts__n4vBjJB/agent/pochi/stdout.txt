# Scalekit SaaSKit: Build an Express.js Web App with Explicit Access Token Refresh ## Background Scalekit SaaSKit (Full-Stack Auth) issues a short-lived `accessToken`, a long-lived `refreshToken`, and an `idToken` after a successful hosted login. When the access token nears expiry, your app can exchange the refresh token for a brand-new pair of tokens by calling the SDK's `refreshAccessToken` method — without forcing the user to sign in again. In this task you will build a small Express.js web application that wires SaaSKit end-to-end **and** exposes a user-visible "Refresh access token" control on the dashboard. A real human user (driven by a browser agent during verification) will sign in with the preconfigured test user + static OTP, land on a protected dashboard that shows the access token's current `iat` (issued-at) and `exp` (expires-at) claim values, click "Refresh access token", and see the dashboard re-render with new `iat`/`exp` values that come from a freshly issued token returned by Scalekit's refresh API. The Scalekit environment has been preconfigured with the following SaaSKit fixtures (use them verbatim, do **NOT** invent new credentials, do **NOT** introduce any environment variables that are not provided): * Allowed callback URL: `http://localhost:3000/callback` * Initiate-login URL: `http://localhost:3000/login` * Post-logout URL: `http://localhost:3000/goodbye` * Test user email: `zealt-user01+sktest@test.com` * Static OTP for the test user: `424242` Scalekit SDK credentials are provided through the environment variables `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, and `SCALEKIT_CLIENT_SECRET`.
