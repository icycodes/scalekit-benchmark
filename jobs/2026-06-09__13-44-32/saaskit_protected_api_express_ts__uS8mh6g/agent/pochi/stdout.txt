# Scalekit SaaSKit: Build an Express.js Web App with a Token-Validated Protected JSON API ## Background Scalekit SaaSKit (Full-Stack Auth) issues an `access_token`, `id_token`, and `refresh_token` after a successful hosted login. A production-grade app must **validate** the access token server-side before trusting any embedded claims (the `validateAccessToken` SDK call). The same pattern is used to protect first-party JSON APIs that the browser dashboard calls on behalf of the signed-in user. In this task you will build a small Express.js web application that wires SaaSKit end-to-end **and** uses `scalekit.validateAccessToken()` as the gate for both a protected HTML dashboard and a protected JSON `/api/me` endpoint. A real human user (driven by a browser agent during verification) will sign in with the preconfigured test user + static OTP, land on the dashboard, see their own user information (which the dashboard pulls from the same `/api/me` JSON endpoint that an unauthenticated caller cannot reach), and finally sign out. ## Key Design Decisions

- **Shared middleware**: `requireValidAccessToken` is reused for both `/dashboard` (HTML) and `/api/me` (JSON), with the route handler checking `req.authError` to decide how to fail (redirect vs 401 JSON).
- **Token extraction**: Supports both HttpOnly cookie (`accessToken`) and `Authorization: Bearer <token>` header.
- **Logout ordering**: `getLogoutUrl` is called **before** clearing the `idToken` cookie, since the ID token is needed as `id_token_hint`.
- **JWT decoding**: The idToken payload is base64url-decoded (no crypto verification needed — `validateAccessToken` already verifies the access token through Scalekit).
