After a successful login, the application stores three session tokens (`accessToken`, `refreshToken`, `idToken`) as HttpOnly cookies. Your job is to implement a correctly-behaved server-side logout endpoint that ends both the application session layer and the Scalekit session layer in a single browser redirect. This logout flow has a few narrow pitfalls (browser redirect vs. API call, ID-token-hint requirement, the cookie-clear ordering) that must be respected. The Scalekit Node SDK exposes a `getLogoutUrl(idTokenHint, postLogoutRedirectUri)` helper which builds the correct URL targeting Scalekit's `/oidc/logout` endpoint. ## Requirements * Build a small Express + TypeScript app that exposes a `GET /logout` route. * The route MUST: * Read the `idToken` value from the request's cookies (use `cookie-parser`). * Use `ScalekitClient.getLogoutUrl(idTokenHint, postLogoutRedirectUri)` to build the Scalekit logout URL. The `postLogoutRedirectUri` MUST be `http://localhost:3000/goodbye` (this URL is preregistered in the dashboard). * Clear the three session cookies (`accessToken`, `refreshToken`, `idToken`). * Respond with an HTTP 302 redirect whose `Location` header is the Scalekit logout URL. * The Scalekit client MUST be initialized from the environment variables `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, and `SCALEKIT_CLIENT_SECRET`. * Provide a `GET /goodbye` route that responds with HTTP 200 and the plain-text body `Goodbye` so that the post-logout redirect target is reachable for manual smoke testing. ##
