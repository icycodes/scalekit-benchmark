# Scalekit SaaSKit: Build an Express.js Web App with a Token-Validated Protected JSON API ## Background Scalekit SaaSKit (Full-Stack Auth) issues an `access_token`, `id_token`, and `refresh_token` after a successful hosted login. A production-grade app must **validate** the access token server-side before trusting any embedded claims (the `validateAccessToken` SDK call). The same pattern is used to protect first-party JSON APIs that the browser dashboard calls on behalf of the signed-in user. In this task you will build a small Express.js web application that wires SaaSKit end-to-end **and** uses `scalekit.validateAccessToken()` as the gate for both a protected HTML dashboard and a protected JSON `/api/me` endpoint. A real human user (driven by a browser agent during verification) will sign in with the preconfigured test user + static OTP, land on the dashboard, see their own user information (which the dashboard pulls from the same `/api/me` JSON endpoint that an unauthenticated caller cannot reach), and finally sign out. The Scalekit environment has been preconfigured with the following SaaSKit fixtures (use them verbatim, do **NOT** invent new credentials, do **NOT** introduce any environment variables that are not provided): * Allowed callback URL: `http://localhost:3000/callback` * Initiate-login URL: `http://localhost:3000/login` * Post-logout URL: `http://localhost:3000/goodbye` * Test user email: `zealt-user01+sktest@test.com` * Static OTP for the test user: `424242` Scalekit SDK credentials are provided through the environment variables `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, and `SCALEKIT_CLIENT_SECRET`. No other Scalekit environment variables exist. ## Requirements * Build an Express.js application (Node.js) using the official `@scalekit-sdk/node` SDK. TypeScript or plain JavaScript is acceptable. * The app **MUST** listen on port `3000` so it matches the registered SaaSKit URLs above. * Implement the following routes: * `GET /` — a public landing page. Must render an HTML page that contains a visible sign-in entry point (link/button) whose target is `GET /login`. * `GET /login` — builds the SaaSKit authorize URL via the Scalekit SDK with the registered callback URL `http://localhost:3000/callback` and scopes that include `openid`, `profile`, `email`, and `offline_access`, then HTTP-redirects (302/303/307) the user to that URL. The authorize URL **MUST** be generated by the SDK (do not hand-build it). * `GET /callback` — receives `?code=<...>`, exchanges it via the Scalekit SDK (`authenticateWithCode`), stores `accessToken`, `refreshToken`, and `idToken` in **HttpOnly** cookies, and HTTP-redirects to `/dashboard`. * `GET /dashboard` — a protected HTML route. The handler **MUST** validate the `accessToken` cookie via `scalekit.validateAccessToken(accessToken)` before rendering. If the cookie is missing or `validateAccessToken` returns falsy, HTTP-redirect to `/login`. If valid, render an HTML page that visibly contains BOTH the signed-in user's email (decoded from the `idToken` `email` claim) AND the user's Scalekit `sub` user id (decoded from the `idToken` `sub` claim), along with a visible "Sign out" / "Logout" link or button targeting `GET /logout`. * `GET /api/me` — a protected JSON endpoint: * The handler **MUST** read the `accessToken` cookie (or an `Authorization: Bearer <token>` header) and call `scalekit.validateAccessToken(accessToken)` to gate access. * If the access token is missing or `validateAccessToken` returns falsy, respond with HTTP **401** and a JSON body of the shape `{ "error": "<some message>" }` (the response content-type MUST be `application/json`). * If valid, respond with HTTP **200** and a JSON body that contains AT LEAST the fields `email` (from the `idToken` `email` claim) and `sub` (from the `idToken` `sub` claim). Extra fields are allowed. * `GET /logout` — produce the Scalekit logout URL via `scalekit.getLogoutUrl(idToken, 'http://localhost:3000/goodbye')` **BEFORE** clearing cookies, then clear `accessToken`, `refreshToken`, and `idToken` cookies and HTTP-redirect the browser to the logout URL. * `GET /goodbye` — a public page that visibly confirms the user has signed out (must contain a clearly visible "signed out" / "goodbye" / "logged out" message). ## Implementation Hints * Install the SDK with `npm install @scalekit-sdk/node express cookie-parser` (add `typescript`/`tsx` if you want to write TypeScript). * Initialize the SDK with `new ScalekitClient(process.env.SCALEKIT_ENV_URL!, process.env.SCALEKIT_CLIENT_ID!, process.env.SCALEKIT_CLIENT_SECRET!)`. The same client exposes the SaaSKit helpers you need (`getAuthorizationUrl`, `authenticateWithCode`, `validateAccessToken`, `getLogoutUrl`). * The redirect URI passed to `getAuthorizationUrl` and `authenticateWithCode` **MUST** be `http://localhost:3000/callback` exactly — protocol, host, port, and path must match the dashboard allow-list (do not substitute `127.0.0.1`). * `scalekit.validateAccessToken(token)` returns a boolean (truthy = valid). Treat any thrown error as "invalid token" — never let it crash the request handler. * Centralize the token validation in a small middleware function and reuse it for both `/dashboard` and `/api/me`. On the JSON endpoint the failure response must be a JSON 401 body; on the HTML route the failure response must be a 3xx redirect to `/login`. * The id token is a JWT. Decode its payload (e.g., with a small base64url decode) to read the `email` and `sub` claims for both the dashboard page and the `/api/me` JSON body. You do **NOT** need to cryptographically verify the JWT — `validateAccessToken` already verifies the related access token through Scalekit. * Logout has to be a browser redirect to `/oidc/logout`, not a `fetch()` POST — the Scalekit session cookie only travels with a real browser navigation. Generate the logout URL **before** clearing the `idToken` cookie because the ID token is required as `id_token_hint`. * Use `cookie-parser` (or equivalent) to read cookies on subsequent requests. * Provide a `package.json` with a `start` script (or equivalent) so the app can be launched with `npm start` from the project directory. * This task does **NOT** create any external resources beyond a short-lived Scalekit auth session, so no `run-id` suffix is required. ## Acceptance Criteria * Project path: `/home/user/myproject` * Start command: `npm start` * Port: `3000` * Routes (each must respond with the documented behavior): * `GET /` → HTTP 200 HTML page containing a visible sign-in link/button whose target is `/login`. * `GET /login` → HTTP 3xx redirect whose `Location` is a Scalekit-hosted authorize URL (`https://...` containing `/oauth/authorize`, `response_type=code`, a `client_id` parameter, `redirect_uri` URL-decoding to exactly `http://localhost:3000/callback`, and `scope` URL-decoding to a value that includes all of `openid`, `profile`, `email`, and `offline_access`). * `GET /callback?code=<...>` → on success sets `accessToken`, `refreshToken`, and `idToken` as **HttpOnly** cookies and HTTP-redirects to `/dashboard`. * `GET /dashboard` (no cookies) → HTTP 3xx redirect whose `Location` ends with `/login`. * `GET /dashboard` (with an obviously bogus `accessToken` cookie value such as `not-a-real-token`) → HTTP 3xx redirect whose `Location` ends with `/login` (the SDK validation must reject it). * `GET /dashboard` (authenticated, valid session) → HTTP 200 HTML page that visibly contains BOTH the signed-in user's email AND their Scalekit `sub` user id (a string that starts with `usr_`), along with a visible "Sign out" / "Logout" link/button targeting `/logout`. * `GET /api/me` (no cookies, no Authorization header) → HTTP 401 with a JSON body of shape `{ "error": <string> }` and a `Content-Type` that includes `application/json`. * `GET /api/me` (with an obviously bogus `accessToken` cookie value such as `not-a-real-token`) → HTTP 401 with a JSON body of shape `{ "error": <string> }` and a `Content-Type` that includes `application/json`. * `GET /logout` → HTTP 3xx redirect to a Scalekit-hosted URL whose path contains `logout` (e.g., `/oidc/logout`), whose query string includes a non-empty `id_token_hint` parameter and a `post_logout_redirect_uri` URL-decoding to `http://localhost:3000/goodbye`. The response must clear `accessToken`, `refreshToken`, and `idToken` via `Set-Cookie`. * `GET /goodbye` → HTTP 200 HTML page containing a clearly visible "signed out" / "goodbye" / "logged out" confirmation message. * End-to-end browser flow: starting from `/`, clicking the visible sign-in entry point and completing Scalekit's hosted login with the preconfigured test user email `zealt-user01+sktest@test.com` and static OTP `424242` MUST land the user on `/dashboard`, where the page visibly shows that email AND a `usr_...` user id. Clicking the sign-out control on the dashboard MUST end the session at `/goodbye` with a visible sign-out confirmation message.
