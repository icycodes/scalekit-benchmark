## Routes Implemented

| Route | Behavior |
|-------|----------|
| `GET /` | Public landing page with a "Sign In" link pointing to `/login` |
| `GET /login` | 302 redirect to Scalekit's `/oauth/authorize` URL with scopes `openid profile email offline_access` and redirect_uri `http://localhost:3000/callback` |
| `GET /callback?code=<...>` | Exchanges the authorization code for tokens via direct HTTP POST to Scalekit's `/oauth/token` endpoint, sets `accessToken`, `refreshToken`, and `idToken` as **HttpOnly** cookies, then 302 redirects to `/dashboard` |
| `GET /dashboard` | Protected route — redirects to `/login` if no `idToken` cookie; otherwise decodes the JWT and renders the user's email with a "Sign Out" link to `/logout` |
| `GET /logout` | Constructs the Scalekit `/oidc/logout` URL with `id_token_hint` and `post_logout_redirect_uri`, clears all three auth cookies, then 302 redirects to the logout URL |
| `GET /goodbye` | Public page confirming the user has signed out |

## Key Implementation Details
- Uses `@scalekit-sdk/node`'s `ScalekitClient.getAuthorizationUrl()` for the login redirect
- Makes a direct HTTP POST to `${SCALEKIT_ENV_URL}/oauth/token` for token exchange (to capture `refresh_token` which the SDK's `authenticateWithCode` doesn't expose)
- Constructs the logout URL manually (the SDK doesn't have a `getLogoutUrl` method)
- JWT payload decoded client-side (without verification) to extract the `email` claim for the dashboard
- All auth cookies are set with `httpOnly: true` and `path: '/'`
- The logout URL is built **before** clearing the `idToken` cookie (since `id_token_hint` needs the token value)
- App listens on port 3000, launched via `npm start`
