## Route implementation

| Route | Behaviour |
|---|---|
| `GET /` | Landing page with a **"Sign in with SSO"** `<a>` pointing to `/login` |
| `GET /login` | Calls `scalekit.getAuthorizationUrl(REDIRECT_URI, { scopes: ['openid','profile','email','offline_access'] })` → 302 to Scalekit's hosted authorize URL |
| `GET /callback` | Calls `scalekit.authenticateWithCode(code, REDIRECT_URI)`, sets `accessToken`, `refreshToken`, `idToken` as **HttpOnly** cookies, 302 → `/dashboard` |
| `GET /dashboard` | No `idToken` cookie → 302 `/login`; otherwise base64url-decodes the JWT payload, renders the user's **email** and **oid** (`org_*`) and a **"Sign out"** link to `/logout` |
| `GET /logout` | Calls `scalekit.getLogoutUrl(idToken, 'http://localhost:3000/goodbye')` **before** clearing cookies, clears all three cookies via `Set-Cookie`, 302 → Scalekit `/oidc/logout` URL |
| `GET /goodbye` | Public page confirming **"You have been signed out"** |

## Key design decisions

- **`REDIRECT_URI`** is hard-coded to `http://localhost:3000/callback` (exact match for the dashboard allow-list).  
- **`getAuthorizationUrl`** is used SDK-side — the URL is never hand-built.  
- **`getLogoutUrl`** is called before `clearCookie` so the `idToken` is still available as `id_token_hint`.  
- JWT payload is decoded with a plain base64url decode (no crypto verification needed post-OIDC exchange).  
- All HTML output is HTML-escaped via `escapeHtml()` to prevent XSS from claim values.
