# Scalekit SaaSKit: Build an Express.js Web App that Drives Enterprise SSO via Home Realm Discovery

## Background
Scalekit SaaSKit (Full-Stack Auth) supports **Enterprise SSO** with **Home Realm Discovery (HRD)**: when a user signs in with an email whose domain is registered to an organization that has an SSO connection, Scalekit automatically routes that user to the organization's identity provider instead of any first-party authentication method. For local testing, Scalekit provides an IdP Simulator that acts as a stand-in IdP for the preconfigured Test Organization.

In this task you will build a small Express.js web application that wires SaaSKit end-to-end so a real human user (driven by a browser agent during verification) can:

1. Open the landing page.
2. Click "Sign in with SSO".
3. Type an email belonging to the test organization's registered domain on Scalekit's hosted login page.
4. Be automatically redirected by Scalekit (via Home Realm Discovery) to Scalekit's IdP Simulator.
5. Complete authentication on the IdP simulator.
6. Land on a protected dashboard that displays their signed-in email and their Scalekit organization id (the `oid` claim from the issued ID token).
7. Sign out cleanly via the Scalekit logout endpoint and end up on a public goodbye page.

The Scalekit environment has been preconfigured in the dashboard with the following fixtures (use them verbatim, do **NOT** invent new credentials, do **NOT** introduce any environment variables that are not provided):

* Allowed callback URL: `http://localhost:3000/callback`
* Initiate-login URL: `http://localhost:3000/login`
* Post-logout URL: `http://localhost:3000/goodbye`
* Test organization registered domains for Home Realm Discovery: `example.com`, `example.org`
* Test organization SSO connection is wired to Scalekit's hosted IdP Simulator

The Scalekit SDK credentials are provided through the environment variables `SCALEKIT_ENV_URL`, `SCALEKIT_CLIENT_ID`, and `SCALEKIT_CLIENT_SECRET`. No other Scalekit environment variables exist.

## Requirements
- Build an Express.js application (Node.js) using the official `@scalekit-sdk/node` SDK. TypeScript or plain JavaScript is acceptable.
- The app **MUST** listen on port `3000` so it matches the registered callback / initiate-login / post-logout URLs above.
- Implement the following routes:
  - `GET /` — a public landing page. It must render an HTML page that contains a visible "Sign in with SSO" entry point (a link or button) that takes the user to `GET /login`.
  - `GET /login` — builds the SaaSKit authorize URL via the Scalekit SDK with the registered callback URL `http://localhost:3000/callback` and a scope set that includes `openid`, `profile`, `email`, and `offline_access`, then HTTP-redirects (302/303/307) the user to that URL. The authorize URL **MUST** be generated by the SDK (do not hand-build it).
  - `GET /callback` — receives `?code=<...>`, exchanges it via the Scalekit SDK (`authenticateWithCode`), stores `accessToken`, `refreshToken`, and `idToken` in **HttpOnly** cookies, then HTTP-redirects to `/dashboard`.
  - `GET /dashboard` — a protected route. If the request has no valid session (no `idToken` cookie), redirect to `/login`. If authenticated, render an HTML page that shows BOTH the signed-in user's email (decoded from the `idToken` claim `email`) AND the user's Scalekit organization id (decoded from the `idToken` claim `oid`), and a visible "Sign out" / "Logout" link or button targeting `GET /logout`.
  - `GET /logout` — produce the Scalekit logout URL via `scalekit.getLogoutUrl(idToken, 'http://localhost:3000/goodbye')` BEFORE clearing cookies, then clear `accessToken`, `refreshToken`, and `idToken` cookies, and HTTP-redirect the browser to the logout URL.
  - `GET /goodbye` — a public page that visibly confirms the user has signed out (must contain a clearly visible "signed out" / "goodbye" / "logged out" message).

## Implementation Hints
- Install the SDK with `npm install @scalekit-sdk/node express cookie-parser` (add `typescript`/`tsx` if you want to write TypeScript).
- Initialize the SDK with `new ScalekitClient(process.env.SCALEKIT_ENV_URL!, process.env.SCALEKIT_CLIENT_ID!, process.env.SCALEKIT_CLIENT_SECRET!)`.
- The redirect URI passed to `getAuthorizationUrl` and `authenticateWithCode` **MUST** be `http://localhost:3000/callback` exactly — protocol, host, port, and path must match the dashboard allow-list (do not substitute `127.0.0.1`).
- You do not have to detect SSO yourself; the Scalekit hosted login page performs Home Realm Discovery automatically once the user submits an email whose domain matches a registered organization domain (e.g., `example.com`).
- The id token is a JWT. Decode its payload (e.g., with a small base64url decode) to read the `email` and `oid` claims and display them on the dashboard. You do **NOT** need to cryptographically verify the JWT inside the dashboard handler — Scalekit already issues it through the OIDC code exchange.
- Logout has to be a browser redirect to `/oidc/logout`, not a `fetch()` POST — the Scalekit session cookie only travels with a real browser navigation. Generate the logout URL **before** clearing the `idToken` cookie because the ID token is required as `id_token_hint`.
- Use `cookie-parser` (or equivalent) to read cookies on subsequent requests.
- Provide a `package.json` with a `start` script (or equivalent) so the app can be launched with `npm start` from the project directory.
- This task does **NOT** create any external resources beyond a short-lived Scalekit auth session, so no `run-id` suffix is required.

## Acceptance Criteria
- Project path: `/home/user/myproject`
- Start command: `npm start`
- Port: `3000`
- Routes (each must respond with the documented behavior):
  - `GET /` → HTML page containing a visible "Sign in with SSO" link or button whose target is `/login`.
  - `GET /login` → HTTP 3xx redirect whose `Location` is a Scalekit-hosted authorize URL (`https://...` containing `/oauth/authorize`, `response_type=code`, a `client_id` parameter, `redirect_uri` URL-decoding to exactly `http://localhost:3000/callback`, and `scope` URL-decoding to a value that includes all of `openid`, `profile`, `email`, and `offline_access`).
  - `GET /callback?code=<...>` → on success sets `accessToken`, `refreshToken`, and `idToken` as **HttpOnly** cookies and HTTP-redirects to `/dashboard`.
  - `GET /dashboard` (unauthenticated, no cookies) → HTTP 3xx redirect whose `Location` ends with `/login`.
  - `GET /dashboard` (authenticated, with a valid `idToken` cookie) → HTML page that visibly contains BOTH the signed-in user's email AND the user's `oid` (an `org_*` style organization identifier), along with a visible "Sign out" or "Logout" link/button targeting `/logout`.
  - `GET /logout` → HTTP 3xx redirect to a Scalekit-hosted URL whose path contains `logout` (e.g., `/oidc/logout`), whose query string includes a non-empty `id_token_hint` parameter and a `post_logout_redirect_uri` URL-decoding to `http://localhost:3000/goodbye`. The response must clear `accessToken`, `refreshToken`, and `idToken` via `Set-Cookie`.
  - `GET /goodbye` → HTML page containing a clearly visible "signed out" / "goodbye" / "logged out" confirmation message.
- End-to-end browser flow: starting from `/`, clicking the visible "Sign in with SSO" entry point and entering an email under the test organization's registered domain (`example.com`) on Scalekit's hosted login page must trigger Home Realm Discovery, redirect the browser to Scalekit's IdP Simulator, allow the simulator to complete authentication, and land the user on `/dashboard` showing that user's email and an `org_*` organization id.
